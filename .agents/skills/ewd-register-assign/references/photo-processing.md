# 사진 처리와 큰 표지 데이터

## QR 추출

에이전트가 사진을 먼저 보고 QR 존재 여부·자료 번호·인접한 읽기/정따 문구를 확인한다.
스크립트는 QR 원문과 HTTP(S) 주소만 추출하며 책 제목·용도·배정 순서는 결정하지 않는다.
QR이 없는 그림책 표지에는 부모가 직접 준 읽기 링크를 사용해도 된다.

`scripts/decode-qr.mjs`는 현재 저장소에 설치된 `sharp`와 `jsqr`를 사용한다.
저장소 루트에서 실행하며 사진과 DB를 변경하지 않고 네트워크에 접속하지 않는다.
에이전트가 임시 입력 JSON을 작성한다. 부모에게 JSON이나 좌표 작성을 요구하지 않는다.

```json
{
  "images": [
    { "path": "books/Scanned_20261004-2222-03.jpg" },
    {
      "path": "books/Scanned_20261004-2201-01.jpg",
      "regions": [
        { "label": "listen", "left": 360, "top": 265, "width": 400, "height": 385 },
        { "label": "shadow", "left": 1590, "top": 275, "width": 342, "height": 375 }
      ]
    }
  ]
}
```

위 영역은 이번 `What Is It?` 사진의 예시다. 다른 사진에는 원본 픽셀 크기에 맞춰
QR 주변의 흰 여백까지 포함한 영역을 지정한다. `label`은 에이전트가 사진에서 판별한
위치 이름이며 필드 배치를 자동 승인하지 않는다. 경로는 실행 디렉터리 기준이다.

```bash
node .agents/skills/ewd-register-assign/scripts/decode-qr.mjs /tmp/ewd-qr-input.json > /tmp/ewd-qr-result.json
```

- 영역 미지정: 전체 사진의 1/4·1/2·원본 크기를 시도한다.
- 영역 지정: 지정 영역만 처리한다. 폭 300·500·700px에 원래 색상과 임계값
  120·150·180 이진화를 조합해 시도한다. 각 시도에서 찾은 QR을 가려 같은 사진의
  다른 QR도 추출한다.
- 결과는 사진별·영역별 `raw`, `url`, 성공한 `attempts`다. `URL:` 접두사는
  `url`에서만 제거하고 원문은 보존한다. HTTP(S)가 아닌 원문은 `url: null`이다.
  빈 `results`는 해당 시도로 인식하지 못했다는 뜻이다.
- 결과가 여러 개면 실제 QR 수·위치를 확인한다. 한 QR 영역에서 다른 주소가 나오거나
  다른 디코더 결과와 충돌하면 확정하지 않는다. 인식 결과 순서는 배정 순서가 아니다.
- 전체 사진에서 누락된 QR만 영역을 지정해 재시도한다. 필요하면 다른 무료 디코더로
  교차 확인한다. 실용적인 재시도 뒤에도 실패하면 그 링크만 부모에게 요청한다.

이번 5장·6개 QR은 전체 사진 처리로 3개, 영역 지정·축소·이진화로 나머지 3개를
읽었다. 두 그림책의 QR 사진은 제공되지 않아 부모가 YouTube 링크로 보완했다.
이 결과를 향후 사진 전체의 성공률이나 실제 오디오 재생 확인으로 일반화하지 않는다.

## 표지 포함 데이터 전달

표지는 계속 `lib/cover-image.ts`의 `compressCoverImage()`로 처리한다.
`decode-qr.mjs`의 축소·이진화 결과를 표지로 저장하지 않는다.
성공했던 임시 도구 경로를 전제로 삼지 말고 현재 환경의 브라우저·의존성을 확인한다.

이번 7권의 표지와 배정 데이터를 포함한 JSON은 약 1.45MB였고, 큰 출력 토큰 예산을
설정해도 도구 출력이 잘렸다. 토큰 예산 증가만으로 완전한 전달을 보장하지 않는다.

1. 로컬에 후보 JSON을 저장하고 바이트 길이와 SHA-256을 기록한다. 원본 사진은 보존한다.
2. 도구 출력 한도를 넘으면 작은 조각으로 읽어 에이전트 실행 환경에서 순서대로
   재조립한다. UTF-8 바이트 경계를 중간에서 해석하지 않도록 바이트를 합친 뒤 디코딩하거나,
   텍스트 문자 위치 기준으로 나눈다. 요약 로그에 base64 전체를 출력하지 않는다.
3. 재조립한 바이트 길이·SHA-256과 JSON 파싱 성공을 확인하고 책·배정 수와 ID를
   후보에 대조한다. 불완전한 데이터를 DB에 전달하지 않는다.
4. 저장 직전 중복·겹침을 다시 확인하고 트랜잭션에서 동시 변경도 방어한다.
   응답이 불명확하면 먼저 재조회하고 확인된 누락만 처리한다.
5. 저장 후 메타데이터와 배정의 모든 요청 필드를 대조한다. 표지는 전체 base64를
   응답으로 가져오는 대신 동일 data URL의 길이·해시·형식을 대조할 수 있다.
   실제 앱의 표지 표시·오디오 실행 검증은 별도로 기록한다.

특정 조각 크기나 잠금 방법을 모든 환경에 고정하지 않는다. 도구 제한에 맞춰 조절하되
완전한 전달, 소유 확인, 동시 변경 방어와 저장 후 검증을 유지한다.
