# Phase 3 — 보고서와 통합 검증

상태: 구현 대기. 선행: [Phase 2](02-child-record.md). 범위와 수용 기준: [부모 보고서와 최종 검증](../tasks/04-report-and-verification.md).

목표: DVD 시청 시간과 읽기 시간을 분리해 화면과 PDF에 일관되게 표시하고 전체 흐름을 검증한다. 각 구현 step은 실패 테스트 확인 → 최소 구현 → 통과 확인 및 정리 순서로 진행한다.

## Step 1. 기간별 집계

- Red: 한글책 30분·영어 그림책 40분·DVD 60분이 읽기 70분과 DVD 60분으로 분리되는 사례를 검증한다. 기록 없음, DVD만, 읽기만, 아동·주·월 전환, 기존 목록 연결 없는 DVD와 범위 밖 과거 시간도 확인한다. 같은 날 60분 두 건은 일·주·월 각각 120분이다.
- Green: DVD를 별도 합산하고 기존 다른 활동의 집계 규칙과 과거 시간 값을 유지한다.
- 확인: 관련 계산 단위 테스트를 실행한다.

## Step 2. 화면과 PDF 표시

- Red: 부모 화면과 주간 PDF에 동일한 분리 합계가 표시되고 활동표의 DVD·한글책·영어 그림책 칸이 유지되는 사례를 검증한다.
- Green: 두 출력에 같은 집계 규칙을 연결한다.
- 확인: 관련 컴포넌트·보고서 브라우저 테스트 및 PDF 출력 결과를 확인한다.

## Step 3. 삭제와 재입력

- Red: DVD 기록 한 건을 삭제하면 그 시간만 합계에서 빠지고 다른 기록과 공통 목록이 유지되며, 올바른 시간으로 재입력할 수 있는 흐름을 검증한다.
- Green: 필요한 연결만 수정하고 기존 부모 수기 기록 삭제 기능을 재사용한다.
- 확인: 관련 저장소·부모 보고서 브라우저 테스트를 실행한다.

## Step 4. 최종 회귀와 기록

- 관련 아동 기록·부모 보고서 브라우저 테스트와 모바일·아동 완료 흐름을 실행한다. `npm run check:pwa`, `npm run typecheck`, `npm run verify`를 실행한다. `verify`에는 브라우저 테스트가 포함되지 않는다.
- 실제 DB 마이그레이션·RLS, 모바일 브라우저와 실기기 PWA 확인 결과를 대역 테스트와 구분한다. 수행하지 못한 검사는 이유와 함께 `review.md`에 기록한다.
- 책 목록·배정 후보·읽은 책 권수와 기존 기록, 보상·완료 조건이 영향을 받지 않았는지 확인한다.

완료 기준: 각 step과 기존 task의 수용 기준이 충족되고 실행 결과 및 남은 검증 한계가 기록되어 있다.
