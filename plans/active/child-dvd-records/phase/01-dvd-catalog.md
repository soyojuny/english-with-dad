# Phase 1 — 가족 공통 DVD 목록

상태: 구현 및 Chromium 제외 검증 완료. 실제 DB RLS와 제외된 브라우저 회귀는 미검증이다. 범위와 수용 기준: [공통 DVD 목록과 부모 관리](../tasks/02-dvd-catalog.md).

목표: 책과 독립된 가족 공통 목록을 저장하고 부모가 제목 추가 및 상태 전환을 할 수 있다. 아동 화면에서 사용할 조회 상태를 제공한다. 각 step은 아래 실패할 테스트를 먼저 작성·실행하고 최소 구현 후 다시 실행한다. 테스트 계층은 기존 구조를 확인해 선택한다.

## Step 1. 목록 계약과 조회

- Red: 빈 목록과 여러 항목의 조회·매핑, 활성/비활성 상태 보존, 책 목록과의 분리를 검증한다.
- Green: 전용 목록의 타입·초기 데이터·저장 매핑과 조회 경로를 필요한 범위에서 추가한다. 소유자별 데이터 경계를 유지하고 기존 책·수기 기록은 변경하지 않는다.
- 확인: 관련 저장소·계약 테스트와 `npm run check:contracts`를 실행한다.

## Step 2. 추가와 상태 전환

- Red: 제목의 앞뒤 공백 제거와 활성 상태로 추가, 빈 제목·공백 거부, 비활성화 후 재활성화 및 기존 시청 기록 보존을 검증한다.
- Green: 목록 추가와 상태 변경을 구현한다. 주간 변경이 목록을 초기화하지 않도록 한다.
- 확인: 관련 저장소 테스트와 주 변경 전후 목록 유지 사례를 실행한다.

## Step 3. DB 소유권 경계

- Red: 소유자는 자신의 목록을 조회·추가·변경할 수 있고 다른 소유자의 조회·변경은 차단되는 사례를 준비한다.
- Green: 전용 테이블 마이그레이션과 `owner_user_id` 기반 RLS를 작성하고 저장 경로와 맞춘다. 기존 기록을 변환하거나 DVD 외래 키를 추가하지 않는다.
- 확인: 계약 검사와 가능한 실제 DB의 마이그레이션·RLS 검증을 실행한다. 대역 테스트만으로 RLS 통과를 주장하지 않으며 환경 제약과 미실행 항목을 `review.md`에 기록한다.

## Step 4. 부모 관리와 아동 조회 상태

각 하위 step을 별도 Red → Green → 검증 주기로 진행하고 완료할 때마다 커밋한다. 실패 원인이 테스트 준비인지 아직 없는 기능인지 구분한다.

### Step 4a. 부모 목록 조회와 상태

- Red: 부모 관리 진입과 DVD 목록의 로딩·오류·빈 목록·항목 표시를 관찰 가능한 화면 동작으로 검증한다.
- Green: 독립된 부모 관리 화면과 가족 목록 조회를 연결한다.
- 확인: 관련 컴포넌트 테스트와 타입 검사를 실행한다.

### Step 4b. 부모의 DVD 추가

- Red: 제목을 입력해 추가하면 보는 중 항목이 표시되고 빈 제목은 거부되는 사례를 검증한다.
- Green: 기존 저장 경로를 화면에 연결하고 저장 중·실패를 처리한다.
- 확인: 관련 컴포넌트 테스트를 실행한다.

### Step 4c. 부모의 상태 전환

- Red: 보는 중에서 안 보는 중으로, 다시 보는 중으로 바꾸는 동작과 실패 시 기존 상태 보존을 검증한다.
- Green: 기존 상태 변경 경로를 화면에 연결한다.
- 확인: 관련 컴포넌트 테스트와 주 변경 후 목록 유지 브라우저 검증을 실행한다.

### Step 4d. 아동용 조회 경계와 최종 확인

- Red: 같은 가족의 두 아동에게 공통 활성 목록이 제공되고 비활성 DVD는 제외되며 로딩·실패·빈 목록을 구분하는 조회 경계를 검증한다.
- Green: Phase 2의 아동 DVD 선택 화면에서 사용할 조회 상태를 제공한다. 실제 아동 DVD 선택 UI 테스트는 Phase 2에서 수행한다.
- 확인: 책 검색·배정 후보·읽은 책 권수와의 분리, 관련 모바일·데스크톱 브라우저 검증, `npm run check:pwa`, `npm run typecheck`, `npm run verify`를 확인한다. 실제 DB와 대역 결과를 구분한다.
- 사용자 요청으로 Chromium 브라우저 회귀는 제외한다. 제외 전 실행된 모바일 주간 이동 검사는 통과했으며, 나머지 브라우저·실기기 및 실제 DB RLS 결과는 [증거 기록](../evidence/phase1.md)에 구분한다.

완료 기준: 위 테스트가 통과하고 목록·기록 분리와 가족 격리의 검증 수준이 기록되어 있다. 실제 DB 검증을 실행할 수 없으면 완료 결과에 미검증 사실을 남긴다.
