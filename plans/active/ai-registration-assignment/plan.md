# AI 자료 등록·할일 배정

## Goal

부모가 순서대로 제공한 표지·QR 사진으로 자료를 등록하고, 합의한 루틴에 따라
1주 또는 2주 할일을 Supabase에 직접 배정한다. 세션 초기화 후에도 합의를 복원할 수
있게 하고 반복 작업을 스킬로 만든다.

## Context

2026-10-04 `grill-with-docs`를 참고한 이전 세션의 요구사항 인터뷰와 선택형 답변을
복원했다. 마지막에 앱 개발보다 Codex의 직접 등록 방식을 먼저 시험하기로 했으며,
그림책 한 권 등록 시험은 부모의 화면 확인까지 완료했다. 후속 대화에서 둘째 정따는
단계별 횟수 대신 일~금 매일 읽기·정따·스스로 읽기 각 1회로 수정했다.

## Decisions

- 전체 합의는 [운영 문서](../../../docs/ai-registration-assignment.md), 실행 루틴은
  [routines.json](../../../.agents/skills/ewd-register-assign/references/routines.json)이 기준이다.
- 부모가 책과 순서를 정하고 시작 일요일·1주/2주·아동·용도를 지정한다.
- 기존 책·할일 데이터 모델, 부모 계정 소유 경계와 RLS를 유지한다.
- 명확한 항목은 요청 범위에서 처리하고 불확실한 정보와 기존 배정 충돌만 확인한다.
- 기존 배정 유지·교체는 부모가 결정하며, 루틴 변경은 새 배정부터 적용한다.
- 로컬 배정 생성기는 DB 쓰기 기능 없이 날짜별 저장 후보를 생성한다.
- 실제 배정 시험은 지정된 아동·책·시작일이 있어야 수행한다.

## Out of Scope

앱 UI·스키마 변경, 상시 폴더 감시, AI의 책 선정, API 구매, 과거 배정의 일괄 변경,
Git 커밋·푸시. 폴더의 구체적 형식은 아직 정하지 않았다.

## Required Verification

- 스킬 frontmatter·참조 파일 검증.
- 배정 생성기의 1주/2주 날짜·책 교체·동시 권수·횟수·퀴즈·토요일 제외 테스트.
- 잘못된 시작일·기간·책 수·중복 입력의 쓰기 후보 생성 거부.
- `npm run check:contracts`; 앱 코드 변경이 없어도 최종 `npm run verify` 실행.
- 실제 배정 전 충돌 조회 및 저장 후 행 재조회; 부모의 실제 앱 표시·오디오 확인.

## ADR Decision

추가 ADR은 필요하지 않다. 기존 저장 구조에 대한 반복 작업 절차를 문서화한다.
