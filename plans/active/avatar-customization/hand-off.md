# 드래곤 에셋 제작 인수인계

작성: 2026-11-04. 다음 세션에서는 이 문서를 먼저 읽고 작업을 이어간다. 소품 생성 프롬프트는 사용자 요청에 따라 채팅에만 제공했다.

## 사용자와 합의한 방향

- 10세·7세 남자아이를 위한 무섭고 멋진 서양 판타지 드래곤. 네 발과 두 날개, 선명한 2D 게임 일러스트. 귀여운 정원 대신 용암·우주·블랙홀 등 웅장한 판타지 공간.
- 주요 기기는 태블릿. 기존 작은 팝업보다 넓은 전체 화면에 가까운 드래곤 공간을 원한다. 실제 앱 화면 변경은 아직 하지 않았다.
- 드래곤에게 장비를 입히지 않는다. 배경·둥지·주변 장식을 꾸민다.
- 이미지 생성은 사용자가 Gemini Nano Banana에서 직접 진행하는 것을 선호한다. 필요한 이미지와 참고 파일, 프롬프트를 채팅으로 제공한다. 임의로 새 디자인을 생성하지 않는다. 투명 배경 분리는 이 세션에서 내장 imagegen으로 처리했다.
- 사용자가 이미지 파일의 vscode-remote URI를 보내면 실제 WSL 경로를 view_image로 확인한다.

## 현재 파일과 승인 범위

기준 디렉터리: `dragon-assets/fire-dragon/`. 파일 대응은 해당 README.md 참고.

- `concepts/baby.png`, `juvenile.png`, `adult.png`: 선택한 불 드래곤 성장 디자인 후보.
- `motions/idle/`: 눈 감기·들숨. `motions/roar/`: 입 열기부터 고개를 높이 들고 포효하는 4단계.
- `motions/fire-breath/charge.png`: 입안에 불이 모인 자세. 실제로는 입이 크게 열려 발사 자세로도 시험 중.
- `effects/fire-stream-source.png`: Gemini에서 만든 길쭉한 화염 줄기 원본.
- `effects/fire-stream-transparent.png`: 내장 imagegen으로 배경을 분리한 파생 시안. 재생성 과정에서 형태가 미세하게 달라질 수 있다.
- `references/`: 초기 및 대안 시안. 삭제하지 않고 보관.
- `combined-preview.html`, `combined-preview.js`: 대기·포효·불 뿜기 통합 시험. 사용자가 동작 확인 완료.
- `blink-preview.html`, `idle-preview.html`, `roar-preview.html`, `fire-breath-preview.html`: 개별 시험. 경로 정리 이후 로딩 확인 완료.

현재 움직임은 완성된 프레임 애니메이션이 아니다. 호흡은 두 그림의 교차 전환, 눈 깜빡임은 눈 주변만 clip-path로 겹침, 포효는 정지 그림 순서 재생, 불길은 한 장의 크기 변화다. 소리 없음. 드래곤 이미지 배경은 아직 불투명하다. 앱·DB·PWA에는 적용하지 않았다.

눈 깜빡임을 전체 이미지로 덮으면 호흡이 갑자기 초기화되는 문제가 있었고 눈 주변만 덮도록 개선해 사용자 확인을 받았다. 불길은 둥근 초기 시안 대신 긴 화염 줄기로 교체했다. 현재 위치는 left:54%, top:33%, width:44%, 드래곤 이미지 너비는 장면의 70%. 배경 합성 시 배치가 달라지면 입 위치를 다시 맞춰야 한다.

## 다음 세션 작업 순서

1. 사용자가 Gemini에서 만들 예정인 화산암 둥지·용암 수정·고대 드래곤 유물 이미지가 있으면 먼저 검토한다. 하나의 이미지에 오브젝트 하나, 배경·드래곤과 분리된 형태가 목표다. 생성 시 성체와 두 번째 용암 배경을 스타일 참고로 첨부하도록 안내했다.
2. 배경 후보를 backgrounds/ 등 알아보기 쉬운 구조로 정리하고 원본 대응 기록을 남긴다. 기존 자료를 무단 삭제하지 않는다.
3. 성체 기본 자세 한 장의 배경을 투명하게 분리한다. 뿔·날개 사이 공간, 먼 쪽의 회색 날개·다리, 어두운 비늘이 손상되지 않는지 확인한다. 원본은 보존하고 별도 파생 파일로 저장한다.
4. 두 번째 용암 배경 위에 성체를 배치해 독립 미리보기에서 크기·발 접지·날개 가독성·불길 대비를 검토한다. 배경이 어두워 검은 드래곤이 묻힐 수 있다. 사용자에게 Chrome으로 보여 주고 검토한다.
5. 기본 합성이 좋으면 눈 감기·호흡·포효·불 뿜기 프레임도 투명화한다. 프레임별 외곽과 크기가 달라지면 튀므로 정렬·합성 상태를 확인한다. 새 배경에서 통합 동작 및 대기 복귀를 재검증한다.
6. 소품과 둥지를 합성해 크기와 레이어 순서, 배치 가능 영역을 시험한다.
7. 실제 앱 통합은 별도 구현 작업. 적용 전에 최신 plan/review/tasks 및 관련 feature/UI/Supabase 스킬을 읽고 현재 요청 범위를 확인한다. 현재 세션의 독립 미리보기를 완료된 앱 기능으로 보고하지 않는다.

그 이후 남은 범위: 아기·청소년 모션, 무속성·번개·얼음·알의 새 에셋, 비행·발차기(미제작), 추가 판타지 배경, 태블릿 전체 화면 UI, 실제 꾸미기 연결, 용량 최적화와 실제 기기 터치·성능 검사. 현재 앱의 속성·성장·보상 규칙을 임의로 바꾸지 않는다.
