# 드래곤 에셋 제작 인수인계

갱신: 2026-11-04. 다음 세션은 이 문서를 먼저 읽는다. 현재 작업은 **사용자 확인을 받은 성체 불 드래곤 독립 합성 시안**이며 실제 앱에 새 원화를 적용한 상태가 아니다.

## 이번 세션 종료 상태

- 사용자는 배경·드래곤·소품 합성 결과를 확인하고 좋다고 답했다. 이후 눈 깜빡임의 얼굴 찡그림, 입에서 떨어진 불길, 느린 포효를 요청했고 보정 결과도 좋다고 확인했다.
- 성체 기본 자세와 동작 7장, 소품 2장을 투명 PNG로 분리했다. 원본과 기존 동작 미리보기는 보존했다.
- 용암 배경 4종, 고대 드래곤 석비, 용암 수정을 합성했다. 배경 전환, 소품 표시/숨김, 시험 배치 2종, 대기·포효·불 뿜기를 확인할 수 있다.
- 사용자 요청에 따라 이 상태와 hand-off를 로컬 커밋한다. 푸시는 요청되지 않았다. 커밋 식별자는 Git 기록 또는 이번 세션 최종 응답을 참고한다.
- 앱 코드·DB·PWA 캐시 변경과 배포는 이번 작업에 포함하지 않았다. 기존 앱의 성장·보상 기능은 이전 원화로 구현되어 있다.

## 합의한 원화 방향과 제작 방식

- 10세·7세 남자아이를 위한 무섭고 멋진 서양 판타지 드래곤. 네 발과 두 날개, 선명한 2D 게임 일러스트.
- 귀여운 정원 대신 용암·우주·블랙홀 등 웅장한 판타지 공간을 지향한다. 주요 기기는 태블릿이며 실제 앱에는 넓은 드래곤 공간 UI가 필요하다.
- 몸에 장비를 입히지 않고 배경·둥지·주변 장식으로 공간을 꾸민다.
- 새 디자인은 사용자가 Gemini Nano Banana에서 직접 생성하는 것을 선호한다. 필요한 이미지·참고 파일·프롬프트를 채팅으로 제공한다. 임의로 새 디자인을 생성하지 않는다. 배경 분리는 내장 imagegen을 사용했다.
- 사용자가 vscode-remote 이미지 URI를 보내면 실제 WSL 경로를 `view_image`로 확인한다.
- **GIF 제작은 다음 필수 단계가 아니다.** 투명 이미지를 앱에서 겹치거나 순서대로 표시해 배경·소품을 분리하고 동작을 개별 실행하는 방향을 설명했고 사용자가 다음 단계 정리에 동의했다. 필요하면 이후 모션 품질에 맞는 다른 형식을 검토한다.

## 최종 보정값과 모션 제한

- 드래곤 8장 모두 1451×1084. 알파 128 초과 외곽의 왼쪽 차이 1px·아래 차이 4px 이내. 같은 캔버스와 CSS 위치를 사용한다.
- 드래곤 위치: left 5%, bottom 4%, width 68%. 장면은 16:9로 유지한다.
- 눈 깜빡임: 중심 76.8%/26.3%, 반경 1.6%/1.1%의 부드러운 타원 마스크. 넓은 사각형이나 얼굴 전체를 덮으면 눈썹·볼까지 바뀌어 찡그림이 생기므로 되돌리지 않는다.
- 불길: left 57.5%, top 35.5%, width 41.5%. 입 안쪽에 연결한 최종 위치다. 드래곤 크기나 위치를 바꾸면 다시 맞춘다.
- 포효: 프레임 간격 135ms, 정점 유지 675ms. 기존보다 총 재생 시간을 25% 줄여 약 1.5초다.
- 호흡: 4초 주기로 기본·들숨 그림 교차 전환. 사용자는 잘 드러나지 않지만 나쁘지 않다고 했으므로 유지했다.
- 완성된 연속 프레임 애니메이션은 아니다. 눈 깜빡임은 눈 영역 겹침, 포효는 정지 그림 순서 재생, 불길은 한 장의 가로 확장이다. 소리는 없다. 이미지 생성 방식의 배경 분리로 미세한 윤곽·색상 변화가 있을 수 있다.

## 다음 세션에서 이어갈 순서

1. **성장 단계 × 속성 에셋 목록부터 확정한다.** 현재 앱 계약은 0일 알, 1일 부화, 6일부터 속성 선택 가능, 18일 청소년, 30일 성체다. 속성 선택을 미루면 청소년·성체도 무속성이다. 속성은 불·번개·얼음이다. `lib/dragon-data.ts`, `lib/dragon-types.ts`, plan/review와 `docs/dragon-rewards.md`를 확인하고 기존 규칙을 바꾸지 않는다.
2. 기본 원화 목록의 출발점은 아래 표다. 기존 자료의 상태를 확인해 재사용 가능/제작 필요를 구분한다. 이 표는 새 원화 제작 목록이며 새 보상·성장 정책을 뜻하지 않는다.

   | 단계 | 필요한 기본 모습 |
   | --- | --- |
   | 알 | 무늬가 다른 3종. 무늬가 속성을 결정하지 않음 |
   | 아기 | 무속성·불·번개·얼음 |
   | 청소년 | 무속성·불·번개·얼음 |
   | 성체 | 무속성·불·번개·얼음. 불 성체는 이번 승인 기준 사용 |

   전체 조합은 알 3종 + 성장 3단계 × 4모습 = 15종이다. 모두 새로 생성한다는 뜻은 아니다. 기존 앱의 무속성 청소년·성체는 색상 필터 표현이므로 전용 새 원화 필요 여부를 구분해 기록한다.

3. **알·무속성 아기·청소년 기본 원화를 우선 검토/제작한다.** 승인된 성체 불 드래곤과 기존 아기·청소년 후보를 참고한다. 먼저 성장 단계들을 나란히 놓고 얼굴·뿔·날개·체형이 같은 드래곤의 성장으로 이어지는지 확인한다. 사용자에게 Gemini용 참고 파일과 프롬프트를 제공하는 방식으로 진행한다.
4. 원화가 정해지면 투명 배경, 여백, 캔버스 크기, 발 접지 위치를 맞춘다. 원본과 파생 파일을 분리하고 대응을 남긴다. 움직임을 먼저 전부 만들었다가 성장 디자인을 다시 바꾸는 순서는 피한다.
5. 단계별 움직임은 기본 원화 이후에 추가한다. 우선 알 흔들림, 아기·청소년의 눈 깜빡임/호흡부터 검토한다. 포효·속성 공격은 단계에 맞게 확장하며 모든 단계에 성체와 같은 동작을 요구하지 않는다. 비행·발차기는 미제작 후속 후보다.
6. 필요한 기본 에셋이 갖춰지면 실제 앱 통합을 별도 작업으로 진행한다. 태블릿용 넓은 공간 UI, 기존 성장·속성·꾸미기 연결, 용량 최적화, 실제 기기 터치·성능을 검증한다. 적용 전 최신 plan/review/tasks와 feature/UI 스킬을 읽고 저장 데이터 변경이 있으면 Supabase 스킬도 적용한다.

다음 세션의 첫 행동은 **현재 에셋 재고와 단계별 제작 필요 목록 정리**다. 이번 승인 시안을 GIF로 변환하거나 앱 통합부터 시작하지 않는다. 이번 시안 승인을 전체 에셋·실제 앱 적용 완료로 해석하지 않는다.
