# 드래곤 에셋 제작 인수인계

## 최신 진행 · 속성별 아기 움직임

- 불·번개·얼음 눈 감기와 들숨 미리보기를 사용자가 승인했다. 파일명과 실제 원화가 다르므로 대응표는 `assets/dragons/README.md`의 속성별 아기 움직임 절을 따른다. 사용자가 제공한 원본은 `baby/`에, 픽셀 분리본은 `baby/element-cutouts/`에 보존한다.
- 승인된 6장을 정식 원본으로 승격하고 앱의 해당 속성 아기에 연결했다. 번개 정식 PNG 이름은 lightning, 앱 WebP 이름은 thunder다. 기존 무속성 움직임·4초 호흡·6초 깜빡임·움직임 줄이기를 유지한다. PWA 캐시는 v7이다.
- 검증 결과와 추가 후속 사항은 `tasks/10-element-baby-motion.md`를 따른다.

## 최신 진행 · 아기 드래곤 동작 미리보기

- 사용자가 Gemini에서 만든 원본 6장은 `baby/`에 보존했다. 무속성 기본 `omauf2…`, 눈 감기 `jpotzl…`, 들숨 `xust2n…`, 불 `bk88ec…`, 번개 `k2bc0k…`, 얼음 `55vooo…`다. 모두 2048×2048이다.
- [아기 미리보기](baby/preview.html)는 `baby/original-cutouts/`의 여섯 투명 PNG를 사용한다. 사용자가 호흡을 좋다고 했고, 눈이 열릴 때 끊김을 수정한 뒤 최종 결과에도 좋다고 답했다. 이 승인은 독립 미리보기의 무속성 동작에 대한 것이다.
- 처음 생성형 배경 분리는 캔버스와 드래곤을 바꿨다. 사용자가 원본 구도 보존을 요청해 `baby/extract-original.cjs`로 회색 배경을 픽셀 기반 분리했다. 불투명하게 남은 픽셀의 RGB가 원본과 동일하고 원본 좌표·2048×2048 캔버스를 유지함을 확인했다. `baby/transparent/`와 `baby/aligned/`는 이전 생성형 분리·정렬 시도이므로 최종 기준으로 사용하지 않는다.
- 미리보기 호흡은 무속성 기본 위에 들숨을 4초 `ease-in-out`으로 교차 투명 전환한다. 깜빡임은 눈 감기 이미지를 중심 74%/34%, 반경 2.8%/2.2%의 가장자리가 부드러운 타원 마스크로 겹친다. 6초 주기이며 opacity 키프레임은 45% 0 → 46.2% 1 → 47.8% 1 → 49% 0이다. 움직임 줄이기 설정에서는 애니메이션을 끈다. 정확한 구현은 미리보기를 기준으로 한다.
- Chromium에서 390·800·1280px 가로 넘침 없이 이미지 전환을 확인했고, 최종 수정 후 마스크·재생·정지도 확인했다. 실제 태블릿 성능은 미검증이다. 미리보기의 동작은 무속성에만 적용되며 속성별 동작 이미지는 없다.
- 사용자가 아기와 속성별 모습을 부화 후 드래곤으로 확정하여 **승인된 픽셀 분리본 6장을 `assets/dragons/source/baby/`로 승격하고 앱용 WebP를 재생성했다.** 정식 PNG는 original-cutouts와 바이트 단위로 동일한 2048×2048이다. 기존 앱의 아기 단계/속성 경로로 연결되며 PWA 캐시는 v5다. `tasks/08-approved-baby-assets.md`가 최신 이관 기록이다.
- 동작 설정은 아직 앱에 연결하지 않았다. 이번 승격은 원화 확정과 배포용 파일 갱신이며 자동 재생·스킬 버튼·성장/DB 규칙은 변경하지 않았다. 배포·커밋·푸시도 포함하지 않았다.

## 최신 상태 · 첫 출시 에셋과 둥지 제거

- 최신 계약은 `tasks/07-release-assets-and-decor.md`. 아래 task 06 및 독립 시안 기록보다 우선한다.
- 앱에는 둥지 없이 배경·장식 1·장식 2만 있다. 배경 4종과 석비·용암 수정만 썸네일로 선택·배치·저장한다. 초기 배경은 용암 계곡이고 초기 소품은 석비·수정이다.
- 정식 원본 PNG 24개는 `assets/dragons/source/`, 앱 배포 WebP는 `public/assets/dragons/`다. `npm run assets:dragons` 및 build의 prebuild에서 정식 원본으로 24개를 생성한다. plans는 제작 이력이며 빌드 의존성이 아니다.
- 알·아기 무속성/불/번개/얼음·불 성체를 새 원화로 표시한다. 후속 액션 프레임도 배포 위치에 준비했으나 자동 액션·스킬 버튼은 연결하지 않았다.
- 연결 DB에는 `dragon_habitat_items`, `dragon_decor_without_nest`를 적용했다. 이미지 바이트·base64는 DB에 넣지 않았다. 카탈로그 식별자와 선택·좌표만 저장한다. 익명 RPC 금지 및 소유자 경계를 유지했다.
- 자동 승인에서 거절한 일괄 초기화/삭제는 하지 않았다. 최종 migration은 기존 행을 건드리지 않는 기본값·조회 규칙·명시적 저장 검증이다. 웹 서버 배포·커밋·푸시는 하지 않았다.

## 합의한 원화 방향과 제작 방식

- 10세·7세 남자아이를 위한 무섭고 멋진 서양 판타지 드래곤. 네 발과 두 날개, 선명한 2D 게임 일러스트.
- 귀여운 정원 대신 용암·우주·블랙홀 등 웅장한 판타지 공간을 지향한다. 주요 기기는 태블릿이며 실제 앱에는 넓은 드래곤 공간 UI가 필요하다.
- 몸에 장비를 입히지 않고 배경·둥지·주변 장식으로 공간을 꾸민다.
- 새 디자인은 사용자가 Gemini Nano Banana에서 직접 생성하는 것을 선호한다. 필요한 이미지·참고 파일·프롬프트를 채팅으로 제공한다. 임의로 새 디자인을 생성하지 않는다. 배경 분리는 내장 imagegen을 사용했다.
- 사용자가 vscode-remote 이미지 URI를 보내면 실제 WSL 경로를 `view_image`로 확인한다.
- **GIF 제작은 다음 필수 단계가 아니다.** 투명 이미지를 앱에서 겹치거나 순서대로 표시해 배경·소품을 분리하고 동작을 개별 실행하는 방향을 설명했고 사용자가 다음 단계 정리에 동의했다. 필요하면 이후 모션 품질에 맞는 다른 형식을 검토한다.

## 최종 보정값과 모션 제한

- 드래곤 8장 모두 1451×1084. 알파 128 초과 외곽의 왼쪽 차이 1px·아래 차이 4px 이내. 같은 캔버스와 CSS 위치를 사용한다.
- 드래곤 위치: left 5%, bottom 4%, width 68%. 장면은 16:9로 유지한다.
- 눈 깜빡임: 중심 76.8%/26.3%, 반경 1.6%/1.1%의 부드러운 타원 마스크. 넓은 사각형이나 얼굴 전체를 덮으면 눈썹·볼까지 바뀌어 찡그림이 생기므로 되돌리지 않는다.
- 불길: left 57.5%, top 35.5%, width 41.5%. 입 안쪽에 연결한 최종 위치다. 드래곤 크기나 위치를 바꾸면 다시 맞춘다.
- 포효: 프레임 간격 135ms, 정점 유지 675ms. 기존보다 총 재생 시간을 25% 줄여 약 1.5초다.
- 호흡: 4초 주기로 기본·들숨 그림 교차 전환. 사용자는 잘 드러나지 않지만 나쁘지 않다고 했으므로 유지했다.
- 완성된 연속 프레임 애니메이션은 아니다. 눈 깜빡임은 눈 영역 겹침, 포효는 정지 그림 순서 재생, 불길은 한 장의 가로 확장이다. 소리는 없다. 이미지 생성 방식의 배경 분리로 미세한 윤곽·색상 변화가 있을 수 있다.

   전체 조합은 알 3종 + 성장 3단계 × 4모습 = 15종이다. 모두 새로 생성한다는 뜻은 아니다. 기존 앱의 무속성 청소년·성체는 색상 필터 표현이므로 전용 새 원화 필요 여부를 구분해 기록한다.

3. **알·무속성 아기·청소년 기본 원화를 우선 검토/제작한다.** 승인된 성체 불 드래곤과 기존 아기·청소년 후보를 참고한다. 먼저 성장 단계들을 나란히 놓고 얼굴·뿔·날개·체형이 같은 드래곤의 성장으로 이어지는지 확인한다. 사용자에게 Gemini용 참고 파일과 프롬프트를 제공하는 방식으로 진행한다.
4. 원화가 정해지면 투명 배경, 여백, 캔버스 크기, 발 접지 위치를 맞춘다. 원본과 파생 파일을 분리하고 대응을 남긴다. 움직임을 먼저 전부 만들었다가 성장 디자인을 다시 바꾸는 순서는 피한다.
5. 단계별 움직임은 기본 원화 이후에 추가한다. 우선 알 흔들림, 아기·청소년의 눈 깜빡임/호흡부터 검토한다. 포효·속성 공격은 단계에 맞게 확장하며 모든 단계에 성체와 같은 동작을 요구하지 않는다. 비행·발차기는 미제작 후속 후보다.
6. 필요한 기본 에셋이 갖춰지면 실제 앱 통합을 별도 작업으로 진행한다. 태블릿용 넓은 공간 UI, 기존 성장·속성·꾸미기 연결, 용량 최적화, 실제 기기 터치·성능을 검증한다. 적용 전 최신 plan/review/tasks와 feature/UI 스킬을 읽고 저장 데이터 변경이 있으면 Supabase 스킬도 적용한다.

다음 세션의 첫 행동은 **현재 에셋 재고와 단계별 제작 필요 목록 정리**다. 이번 승인 시안을 GIF로 변환하거나 앱 통합부터 시작하지 않는다. 이번 시안 승인을 전체 에셋·실제 앱 적용 완료로 해석하지 않는다.
