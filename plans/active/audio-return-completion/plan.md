# 안드로이드 PWA 오디오 복귀와 완료 저장 안정화 계획

## Goal

안드로이드에 설치한 PWA에서 오디오를 듣고 돌아온 후 완료를 눌러도 반영되지 않는 문제를 우선 조사한다. 완료 버튼이 보이지 않는 문제도 별도로 재현하고, 오디오 실행·복귀·완료 저장 흐름을 작은 범위로 리팩토링한다.

사용자는 안드로이드 설치형 PWA와 두 증상을 확인한 뒤 TDD 구현을 승인했다. Herdr의 개발 pane과 테스트 pane을 분리하고, 각 step 완료 시 현재 main에 커밋한다. push/배포는 하지 않는다. 시작 기준 커밋은 `15c82a4da8b8278ac649ed4aecd8ba1e0239f7c7`이다.

## Context

사용자가 확인한 환경과 증상:

- 안드로이드 홈 화면에 설치한 PWA.
- 가장 중요한 문제: 완료 버튼을 눌러도 반영되지 않을 때가 있다.
- 추가 문제: 완료 버튼이 보이지 않을 때가 있다.
- 정확한 오류 문구, 재현 빈도, 청취 시간, 네트워크 상태는 아직 확인하지 않았다.

용어는 기존 Task 모델을 유지한다. 링크를 여는 행위, 앱에 돌아오는 행위, 사용자가 완료를 확인하는 행위는 각각 다르다. 앱 복귀만으로 학습 완료를 처리하지 않는다. 외부 오디오의 실제 재생 완료를 관측하는 기능은 현재 없다.

### 현재 흐름과 확인한 취약점

| 지점 | 코드 근거 | 확인한 동작과 영향 |
| --- | --- | --- |

| 완료 버튼 표시 | `app/reading-manager-client.tsx:1899` | 배정이 선택되고, 실행 기록이 있고, 목표 횟수 미만일 때 표시한다. `returnedAt`은 표시 조건이 아니다. 복귀 시간 누락만으로 버튼이 사라지지는 않는다. |
| 재로드 후 선택 | `app/reading-manager-client.tsx:129`, `:452`, `:524` | 프로필만 sessionStorage에 저장한다. 선택한 배정은 메모리 상태이고, 재로드 후에는 오늘의 첫 배정을 선택한다. 청취하던 배정이 첫 번째가 아니면 다른 책의 완료 상태를 보게 될 수 있다. |

위 항목은 정적 코드에서 확인한 취약점이다. 실제 보고된 오류의 원인은 아직 재현하거나 확정하지 않았다. 특히 중복 요청 방지만으로 단일 클릭의 무반응이 해결된다고 가정하지 않는다.

인증 갱신도 재현 시 확인한다. 설치된 SDK의 `fetchWithAuth`는 토큰 조회를 기다린 뒤 HTTP 요청을 전송하고, Auth 클라이언트는 visible 전환 시 세션 복구를 수행한다. 이는 네트워크 요청 전 대기와 서버 응답 대기를 구별해야 하는 이유이며, SDK 결함이나 교착 상태가 확인되었다는 뜻은 아니다.

## Decisions

승인된 기본 범위:

1. **실패 위치부터 재현한다.** 단일 클릭을 기준으로 핸들러 진입, 인증 대기, HTTP 요청, 응답, 화면 반영을 구분한다. 토큰이나 개인정보를 기록하지 않는 로컬 진단으로 원인을 좁힌다.
2. **작은 단위로 분리한다.** `reading-manager-client.tsx`는 선택한 배정과 UI 연결을 맡는다. 오디오 실행·복귀 조정은 전용 hook으로, 순수 판정과 완료 payload 계산은 `lib/`로 분리한다. 전체 화면 재작성이나 범용 상태 머신 도입은 하지 않는다.
3. **동일 활동의 저장을 직렬화한다.** 클릭 즉시 동기적인 요청 잠금을 잡고 저장 중 상태를 표시한다. 실패하면 해당 활동에 오류와 재시도 동작을 남긴다. 시간 초과는 실패 확정으로 취급하지 않고, 저장 결과 조회와 지연 응답 처리를 설계한 후 재시도를 허용한다.
4. **복귀 저장과 새 실행 저장을 구분한다.** 복귀 저장은 소유자·배정·task·기존 `opened_at`·미복귀 조건이 일치하는 행에만 update한다. 새 실행을 생성하거나 `opened_at`을 수정하지 않는다. 조건 불일치는 최신 상태를 조회하여 처리한다. UI도 같은 실행인지 확인하고 응답을 병합한다.
5. **중복 복귀 이벤트를 한 번으로 처리한다.** 실행 식별과 진행 상태를 React 재렌더 전에 갱신한다. 복귀 시각은 첫 유효 이벤트에서 확보하고, DB 저장 지연으로 완료 계산에서 사라지지 않도록 한다. 초기 렌더나 무관한 focus를 복귀로 오인하지 않도록 이탈·복원 조건을 재현 결과에 맞춰 정한다.
6. **버튼 소실 원인을 따로 확인한다.** 재로드 후 다른 배정 선택이 재현되면, 같은 소유자·아동·날짜에서 유효한 배정 선택을 sessionStorage로 복원한다. 로딩 전 임의의 첫 배정으로 복원 값을 덮어쓰지 않는다. 삭제·날짜 변경·다른 프로필에는 기존 선택 fallback을 적용한다.
7. **현재 학습 규칙을 유지한다.** 사용자가 완료를 눌러야 횟수를 증가시킨다. 복귀 시간이 없어도 수동 완료가 가능하고, 시간이 확인되지 않으면 기존 기본 시간을 사용한다. 한 실행 기록으로 여러 회 완료가 가능한 현재 규칙을 이번 수정에서 바꾸지 않는다.

링크 열기 자체는 인접 점검 항목이다. 현재는 DB 저장 후 `window.open`을 호출하며, 창 열기에 실패해도 실행 기록은 남는다. 사용자 클릭에서 동기적으로 창을 확보하는 방식 등을 검토하되, 실제 실패 흐름과 관계가 확인될 때만 수정 범위에 포함한다. 실행 기록 저장 실패 후의 창 정리와 안내도 함께 검증해야 한다.

## Out of Scope

- 자동 완료, 재생 종료 감지, 최소 청취 시간 강제, 한 번 청취당 한 번 완료 강제.
- 오프라인 완료 큐, 영구 재시도 시스템, 전체 인증 구조 변경, 근거 없는 SDK 교체.
- 여러 기기에서 동시 완료하는 문제까지 해결하는 새 RPC/이벤트 테이블.
- 과제 배정, 부모 보고서, QR, 자료 등록 기능 변경.
- SW 캐시와 설치 동작 변경. 필요성이 확인되면 별도 범위로 판단하고 manifest/SW/PWA 검사를 함께 갱신한다.
- 운영 DB 수정, 배포, push.

기존 테이블과 `owner_user_id`/RLS를 유지하는 방향으로 먼저 검토한다. 새 스키마나 학습 규칙 변경이 필요해지면 계획을 먼저 갱신한다.

### Phase 2 — 복귀와 화면 복원

- **Step 03**: [오디오 복귀 이벤트 관리](tasks/03-pwa-recovery-and-verification.md). 중복 이벤트·이전 응답·로컬 복귀 시간 테스트 RED → 이벤트 조정 로직 GREEN → `fix: coordinate audio return events` 커밋.

### Phase 3 — 최종 검증

- **Step 05**: [전체 검증과 리뷰](tasks/05-final-verification.md). 전체 verify와 브라우저 검증, Standards/Spec 리뷰를 수행한다. 발견된 결함은 먼저 회귀 테스트를 작성하여 수정한 뒤 `test: verify audio completion recovery`로 기록한다. 실제 안드로이드 실기기 검증 가능 여부와 미확인 한계는 명시한다.

### Step 공통 규칙

- 개발 담당은 `audio-dev`, 명령 검증은 `audio-tests` pane을 사용한다. 현재 pane은 진행 관리와 검토를 맡는다. 같은 파일을 동시에 편집하지 않는다.
- 각 코드 step은 테스트를 먼저 작성하고 RED를 확인한 뒤 구현한다. 컴파일 실패로 시작했다면 함수 구현 후 실제 assertion 통과도 확인한다.
- RED/GREEN 실행 결과와 변경 이유는 해당 task와 `review.md`에 기록한다. 의도적으로 실패하는 테스트 상태를 완료 커밋으로 남기지 않는다.
- step마다 관련 테스트와 typecheck를 확인하고 필요한 계약 검사를 실행한다. 완료된 step을 `npm run git:commit`으로 커밋하고 해시를 기록한다.
- 최종 리뷰의 고정점은 위 시작 기준 커밋이며 spec은 이 plan과 모든 task이다.
