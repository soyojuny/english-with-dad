# Step 04 — 보호된 적용과 독립 검증

## What to Build

준비된 배치만 입력받아 책과 배정을 저장하는 Apply 흐름을 만든다. Apply는 책 순서나
URL 용도를 다시 추론하지 않으며, 저장 직전 소유·중복·필수 오디오·활성 상태·기간
충돌을 확인한다. 저장 후에는 별도 조회로 책·표지·배정의 모든 요청 필드를 비교한다.

## Acceptance Criteria

- [ ] 준비된 명세의 전체 해시와 처리 표지 해시를 적용 전에 확인.
- [ ] 부모 소유 아동과 책만 처리하고 다른 `owner_user_id` 행을 읽거나 변경하지 않음.
- [ ] 정규화 제목·오디오 URL 중복과 아동/활동/전체 기간 충돌을 적용 직전에 재검사.
- [ ] 기존 완료·오디오 실행·퀴즈 결과가 있는 행을 암묵적으로 교체하거나 삭제하지 않음.
- [ ] 신규 책·배정을 가능한 한 보호된 단위로 저장하고 unique 충돌 시 재조회.
- [ ] 응답이 불명확하면 전체 배치를 재실행하지 않고 확인된 누락만 처리.
- [ ] 저장된 메타데이터, 표지 길이·해시, 배정 owner/child/date/book/category/tasks/counts/quiz를 비교.
- [ ] 결과 파일에 생성/재사용 ID와 `prepared/applied/db_verified/app_verified` 상태를 기록.
- [ ] DB 검증만으로 실제 로그인 앱 검증을 완료 처리하지 않음.
- [ ] AI 등록 스킬과 운영 문서를 새 파이프라인에 맞게 갱신.

## Required Verification

중복과 충돌이 없는 저장, 저장 직전 경쟁 충돌, 동일 배치 재시도, 응답 유실,
부분 성공/실패, 다른 owner 행, 진행 기록이 있는 교체 시도를 검증한다. Storage를 선택한
경우 파일 업로드와 DB 쓰기가 원자적이지 않은 실패 시나리오 및 고아 파일 정리도 포함한다.

관련 단위/계약/타입 검사를 통과한 뒤 `npm run verify`를 실행한다. 가능한 로그인 세션에서
표지 표시와 오디오 링크 smoke check를 수행하고, 접근할 수 없으면 부모 확인 대기로 기록한다.
