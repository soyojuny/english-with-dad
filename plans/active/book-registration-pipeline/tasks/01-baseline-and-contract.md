# Step 01 — 현재 기준 측정과 처리 계약 확정

## What to Build

코드를 변경하기 전에 앱의 실제 표지 표시 크기, 기존 표지 데이터의 해상도·용량 분포,
현재 등록 경로와 배포 환경의 이미지 처리 제약을 측정한다. 대표 표지 fixture로 해상도,
JPEG/WebP, 품질과 목표 바이트를 비교하고 1차 처리 계약을 확정한다.

## Acceptance Criteria

- [ ] 현재 앱에 별도 이미지 등록 API가 없고 client canvas → Supabase 저장임을 근거와 함께 기록.
- [ ] 모바일·데스크톱에서 표지가 실제로 표시되는 최대 CSS/픽셀 크기를 측정.
- [ ] 기존 표지의 data URL 길이와 디코딩 바이트 분포를 소유자 범위의 집계로 확인.
- [ ] 세로형·정사각형·글자가 작은 표지 등 대표 fixture를 선정하고 원본을 변경하지 않음.
- [ ] 720/960px와 JPEG/WebP 후보의 용량·가독성을 비교.
- [ ] 최대 해상도, 포맷, 초기 품질, 목표 바이트, 품질 하한과 단계 축소 규칙 확정.
- [ ] 1차 저장 위치를 `books.cover` 유지 또는 Storage로 명시적으로 결정.
- [ ] Storage를 선택하면 plan을 갱신하고 RLS·URL·실패 정리·이전 작업을 추가.

## Required Verification

측정 명령과 결과 표를 `review.md`에 남긴다. 운영 표지 전체를 출력하지 않고 집계와
필요한 메타데이터만 조회한다. 대표 이미지의 제목과 작은 글자가 읽히는지 육안 결과와
수치를 함께 기록한다.
