# 아동 화면 읽은 책 기록 팝업 표시 개선

## Goal

아동 화면에서 `읽은 책 기록`을 누르면 페이지 하단으로 이동할 필요 없이, 현재 보고 있는 화면 위에 입력 팝업이 표시되도록 한다.

2026-10-20 사용자의 계획대로 개발 진행 요청에 따라 구현과 검증을 진행한다. 커밋·push·배포는 포함하지 않는다.

## Context

- 진입 버튼: `app/reading-manager-client.tsx`의 `읽은 책 기록` 버튼.
- 대상 팝업: 같은 파일의 `isChildManualLogOpen` 분기, 제목은 `읽은 책 추가`.
- 현재 구조: `<main>` 뒤에 `<dialog className="qr-dialog quick-log-dialog" open>`을 렌더링한다. 이 분기에는 `showModal()` 호출이 없다.
- `styles.css`의 `.qr-dialog`와 `.quick-log-dialog`는 너비와 외형을 지정하며, 화면 중앙 배치나 높이 제한은 지정하지 않는다. `.qr-dialog::backdrop` 스타일은 이미 존재한다.
- 위 내용은 정적 코드 확인 결과다. 실제 브라우저에서 발생하는 좌표와 스크롤 이동은 구현 전 재현으로 확인한다.
- 기존 `tests/browser/client/parent-report.spec.mjs`에 아동 기록 저장 성공, 빈 제목, 저장 실패 검증이 있다. 화면 안에 즉시 표시되는지는 별도 검증이 필요하다.

## Working Contract

확인된 요구사항:

1. 대상은 아동 화면의 읽은 책 기록 입력 팝업이다.
2. 문서 하단 대신 현재 보이는 화면 위에 표시한다.
3. 계획은 `plans/` 아래에 기록한다.

구현 기준 — 2026-10-20 사용자의 계획대로 진행 요청에 따라 채택:

- `frame`은 현재 보이는 브라우저/PWA 화면(viewport)을 뜻하는 것으로 해석한다.
- 충분한 공간에서는 화면 중앙에 모달로 표시하고 배경을 어둡게 처리한다.
- 화면이 짧거나 키보드가 열리면 정확한 중앙 정렬보다 입력란과 버튼 접근을 우선한다. 팝업 높이를 제한하고 필요한 경우 팝업 내부를 스크롤한다.

사용자의 계획대로 개발 진행 요청을 위 추천안에 대한 진행 승인으로 해석한다. 충분한 공간에서는 viewport 중앙에 표시하며, 작은 화면에서는 입력과 버튼 접근을 우선한다.

## Proposed Implementation

1. 해당 팝업을 네이티브 `dialog.showModal()`로 열어 화면 위의 모달로 표시한다. `open` 속성만으로 여는 방식에서 전환하며, 별도의 모달 라이브러리나 범용 팝업 프레임워크는 추가하지 않는다.
2. 팝업의 열기·닫기 수명주기와 JSX는 필요한 경우 `app/child-reading-log-dialog.tsx`로 분리한다. 저장 핸들러와 아동 선택 상태는 기존 화면에서 연결한다.
3. 열림 상태와 실제 dialog 상태를 일치시킨다. 닫기·취소·Escape·저장 성공 후 다시 열 수 있어야 하며, effect 재실행이나 unmount 시 오류가 없어야 한다.
4. 중앙 배치, 화면 여백, 높이 제한과 내부 스크롤은 `.quick-log-dialog`에 한정한다. 배경 조작을 막고, 배경 스크롤 차단이 추가로 필요하면 열려 있는 동안에만 적용하고 닫힐 때 원래 값을 복원한다.
5. 제목으로 접근 가능한 이름을 제공한다. 기존 제목 입력 포커스를 유지하고, Tab 이동은 모달 안에 머물며 닫힌 후 진입 버튼으로 포커스를 복원한다. 열기·닫기 때문에 원래 페이지 위치가 하단으로 이동하지 않아야 한다.
6. 기존 닫기와 취소 버튼에 더해 네이티브 Escape 닫기를 상태와 연결한다. 배경 클릭으로 닫는 기능은 추가하지 않는다.
7. 저장 성공 시 기존처럼 닫고 성공 안내를 표시한다. 저장 실패 시 팝업과 입력값을 유지한다. 모달 전환으로 기존 toast가 뒤에 가려지면 해당 팝업 안에서 오류를 읽을 수 있도록 최소한으로 연결한다.

구현 방식은 브라우저 재현 결과에 따라 세부 조정할 수 있지만, 사용자에게 보이는 표시 위치와 범위는 이 계약을 따른다.

## Scope

예상 변경 파일:

- `app/reading-manager-client.tsx`: 대상 팝업 연결.
- `app/child-reading-log-dialog.tsx`: 분리가 필요한 경우 대상 팝업 UI와 수명주기.
- `styles.css`: 대상 팝업에 한정한 표시와 크기 규칙.
- `tests/browser/client/child-reading-log-dialog.spec.mjs`: 위치 및 모달 동작 회귀 검증.
- 필요할 때만 기존 브라우저 fixture와 아동 수기 기록 테스트를 최소 수정한다.

범위 밖:

- QR 팝업 수정, 다른 팝업 일괄 전환, 화면 전체 재설계.
- 책 구분·기본 시간·오늘 날짜 저장 규칙·입력 검증·저장 payload 변경.
- Supabase 스키마, RLS, 인증, 데이터 계약 변경.
- PWA 캐시·설치 동작 변경, 운영 데이터 수정, 커밋·push·배포.

새 도메인 개념이나 되돌리기 어려운 아키텍처 결정이 없어 `docs/CONTEXT.md`와 ADR은 추가하지 않는다.

## Acceptance Criteria

| 시나리오 | 합격 기준 |
| --- | --- |
| 화면 상단·중간에서 열기 | 별도 페이지 스크롤 없이 현재 화면 안에 팝업이 보인다. 공간이 충분하면 중앙에 표시된다. |
| 긴 과제 목록 위에서 열기 | 문서 끝으로 이동하지 않으며 배경의 버튼을 조작할 수 없다. |
| 모바일 360px·390px / 데스크톱 1280px | 가로 넘침과 문구 겹침이 없고 닫기·입력·저장 버튼에 접근할 수 있다. |
| 짧은 화면·모바일 키보드 | 팝업 내부 스크롤로 입력란과 하단 버튼에 접근할 수 있다. 실기기 키보드 검증 여부를 별도 기록한다. |
| 닫기·취소·Escape 후 재열기 | 상태가 일치하고 정상적으로 다시 열린다. 닫힌 후 진입 버튼 포커스와 페이지 위치를 복원한다. |
| 키보드 조작 | 팝업 이름을 식별할 수 있고, 초기 입력 포커스와 모달 내부 Tab 이동이 동작한다. |
| 정상 저장 | 기존 owner·child·날짜·구분·제목·시간으로 저장되고 팝업이 닫힌다. |
| 빈 제목 / 저장 실패 | 빈 제목은 저장 요청을 만들지 않는다. 실패 시 입력값과 팝업을 유지하며 오류를 읽을 수 있다. |
| 인접 기능 | QR 팝업과 아동 과제 완료 흐름에 회귀가 없다. |

## Required Verification

- 위치 검사는 Playwright 자동 스크롤이나 `scrollIntoViewIfNeeded()` 실행 전에 `getBoundingClientRect()`와 viewport를 비교한다. `toBeVisible()`만으로 화면 안 표시를 판정하지 않는다.
- 정상·경계·잘못된 입력을 검토하고, 신규 테스트에 Given–When–Then 주석을 둔다.
- 신규 팝업 브라우저 테스트, 기존 `parent-report.spec.mjs`, `mobile-layout.spec.mjs`, `camera-upload.spec.mjs`, `child-completion.spec.mjs`를 관련 회귀로 실행한다.
- `npm run check:contracts`, `npm run check:pwa`, `npm run typecheck`, 최종 `npm run verify`를 실행한다. `verify`는 브라우저 테스트를 포함하지 않으므로 별도로 실행한다.
- 모바일 폭 브라우저 검증과 실제 설치형 PWA·가상 키보드 검증을 구별한다. 실행하지 못한 항목은 미검증으로 기록한다.
