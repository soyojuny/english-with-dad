# 반복 절차와 배정 생성기

## What to Build

합의된 요구사항·최신 루틴·진행 상태를 저장하고 사진 인식, 중복 확인, 등록,
루틴 배정, 충돌 처리, 검증을 안내하는 저장소 전용 스킬을 만든다. 반복하는
날짜 계산은 DB에 접속하지 않는 Node 스크립트로 처리한다.

## Acceptance Criteria

- [x] 요구사항과 최신 둘째 정따 규칙을 파일로 보존.
- [x] 부모가 제목·일별 날짜·횟수를 다시 입력하도록 요구하지 않음.
- [x] 6개 아동·용도 루틴의 1주/2주 날짜와 책 교체를 정확하게 생성.
- [x] 사진 매칭, QR 재시도, 표지 압축, 오디오 필드 구분을 안내.
- [x] 기존 배정 충돌은 부모가 선택하고 완료 기록은 자동 삭제하지 않음.
- [x] 저장 요청의 범위를 유지하고 이미 주어진 정보를 다시 묻지 않음.
- [x] 스킬과 생성기 로컬 검증 통과.

## Required Verification

스킬 검증, `node --test .agents/skills/ewd-register-assign/scripts/plan-assignments.test.mjs`,
`npm run verify`.

## Blocked By

없음. 실제 배정 날짜·대상 지정과 독립적으로 준비할 수 있다.

## 실제 등록·배정 후 보완

- [x] 분석·검토 시 DB 조회만 수행하고 후속 실행 요청의 지정 사항을 이어서 적용.
- [x] 실제 사진에서 성공한 전체 축소·QR 영역 자르기·이진화를 `decode-qr.mjs`로 재사용.
- [x] 부모가 직접 준 YouTube 등 HTTP(S) 링크와 쿼리 매개변수 보존.
- [x] 표지 포함 대용량 JSON의 분할 전달·길이·해시·파싱 확인 지침 추가.
- [x] 운영 문서의 아동 이름·앱 별칭·ID와 합의했던 루틴을 재사용하도록 안내.

검증: 실제 사진 5장의 QR 6개가 이전 추출 주소와 일치했다. 생성한 한 사진의 QR
두 개 추출, `URL:` 접두사 처리, 비HTTP 링크 배제, 빈 사진·잘못된 영역 처리와
원본 보존도 확인했다. 스킬 형식·참조 링크·스크립트 구문·기존 배정 테스트 및
`npm run verify`가 통과했다. 앱 코드·배정 규칙·실제 DB 데이터는 변경하지 않았다.
