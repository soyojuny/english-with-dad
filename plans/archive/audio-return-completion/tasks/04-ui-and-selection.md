# Phase 2 / Step 04 — 화면 연결과 배정 선택 복원

## What to Build

먼저 선택 복원과 완료 버튼 표시 조건을 테스트한다. Step 02/03의 로직을 전용 hook과 아동 task UI에 연결한다. 배정 선택은 소유자·아동·날짜별로 sessionStorage에 보관하고 로딩 완료 후 유효한 값만 복원한다. 저장 중/오류/결과 확인 중 상태를 지속적으로 표시한다.

## Acceptance Criteria

- [x] RED: 오늘의 첫 배정이 아닌 선택을 재로드 후 복원한다.
- [x] 삭제된 배정, 다른 소유자/아동/날짜의 선택은 적용하지 않는다.
- [x] 로딩 전에 저장된 선택을 첫 배정으로 덮어쓰지 않는다.
- [x] 완료 버튼은 실행 기록과 목표 횟수에 따른 기존 수동 완료 규칙을 유지한다.
- [x] 저장 중에는 연타를 막고, 저장 실패/미확정 상태는 task에서 보인다.
- [x] 로딩 오류는 기록 없음과 구별한다.
- [x] 복귀 이벤트와 늦은 응답은 활성 프로필에만 적용한다.
- [x] 읽기/정따/단어 읽기 및 스스로 읽기/필사의 기존 횟수·시간 규칙을 유지한다.

## Required Verification

테스트 먼저 작성 → RED → 구현 → GREEN. test:unit/typecheck/check:contracts/check:pwa. 가능한 로컬 브라우저에서 UI 흐름과 모바일 배치를 확인한다.

## Blocked By

Step 02/03.

## TDD Result

- 정책 테스트 먼저 작성: API 누락 컴파일 RED와 기존 정책 stub에서 20개 중 17개 assertion 실패를 확인했다.
- UI 구현 전 실제 컴포넌트 브라우저 테스트 4/4 RED를 기록했다.
- 선택 복원 hook, 완료/복귀 요청 hook, task feedback 컴포넌트를 연결했다. 오래 지연된 완료 요청은 15초 후 결과 미확정 안내로 바꾸며 원래 요청을 유지한다.
- 아동 데이터 로딩 성공 scope를 확인한 뒤에만 배정 선택을 복원/저장한다. 사용자의 직접 선택은 즉시 sessionStorage에 저장한다.
- 단위 테스트 103/103, 타입/계약/PWA 검사 통과. 기존 legacy 완료 upsert 함수와 대응 임시 호환 테스트를 제거했다.
- 동일 브라우저 테스트 4/4 GREEN: 재로드 선택, 저장 중 클릭 차단, 알림 이후 오류 유지, 복귀 DB 응답 전 경과 시간 계산.
- Chromium 390×844 오류 화면을 시각적으로 확인했다. 안내와 버튼은 줄바꿈되며 겹치지 않는다. 안드로이드 실기기는 미확인이다.
