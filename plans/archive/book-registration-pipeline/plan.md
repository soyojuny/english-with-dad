# 책 등록 스킬 안정화 계획

## Status

스킬 보강 완료. [검증 결과](review.md)에 실행 근거와 운영 확인 범위를 기록했다.

## Goal

기존 `ewd-register-assign` 스킬의 지침과 로컬 실행 도구를 안정화한다.
사진·책 순서·아동·용도·오디오 필드·주차를 단일 배치 명세로 확정하고,
브라우저 없이 표지를 압축해 저장 후보와 사람이 읽을 날짜별 배정안을 만든다.

## Working Contract

사용자와 범위를 재확정했다. 이 작업은 시스템 개발이 아니라 **스킬 보강**이다.
이전 계획의 앱/CLI 공용 처리기, 서버 API/Server Action, 동시성 제어 및
자동 Apply 시스템 구현은 제외한다.

- 변경 가능: `.agents/skills/ewd-register-assign/`의 지침·참조·로컬 도구·테스트,
  이 계획과 `docs/ai-registration-assignment.md`.
- 변경 금지: `app/`, `lib/`, `public/`, `supabase/`, 루트 `scripts/`와 `tests/`,
  앱의 `package.json`·lockfile·설정, 기존 배정 생성기와 QR 도구의 코드.
- 앱 코드는 현재 데이터 계약을 확인할 때만 읽는다. 새 API·UI·마이그레이션·Storage
  정책·트랜잭션/잠금·자동 재시도·배포를 만들지 않는다.
- 이 작업에서 운영 DB를 조회하거나 책·배정·기존 표지를 변경하지 않는다.
- 실제 등록은 이후 부모의 자료 등록 요청에 따라 기존 Supabase 도구로 수행한다.
  스킬 개발 승인은 운영 데이터 쓰기 승인이 아니다.

## Local Processing Contract

- 기존 앱의 규격을 로컬 기본값으로 유지한다: JPEG, 긴 변 최대 960px, 품질 72,
  작은 이미지 확대 없음, EXIF 방향 반영, 흰 배경, 메타데이터 제거.
- Sharp와 canvas의 출력 바이트가 같다고 주장하지 않는다. 앱은 수정하지 않는다.
- 720px/WebP 비교와 80~120KB 강제 목표는 이번 범위에서 제외한다.
  실제 처리 전후 해상도·바이트·SHA-256을 출력해 결과를 확인한다.
- 표지 외곽 맞춤은 사용자가 맡는다. 스킬은 단일 입력 표지 전체를 압축하고 원본을
  보존한다. 배경 자르기·원근 보정·별도 보정본 생성과 검토는 하지 않는다.
  EXIF 방향 정규화는 압축 계약에 유지한다.
- 파일 30MiB, 이미지 60메가픽셀을 로컬 입력 상한으로 두고 잘못된 파일은 거부한다.
- 필요한 이미지 의존성은 스킬 디렉터리에서 관리한다. 앱 의존성은 변경하지 않는다.

## Workflow

1. 에이전트가 인식 결과와 부모의 지정으로 단일 명세를 작성한다.
2. 로컬 Prepare가 명세·URL·책 순서를 검사하고 표지와 배정 후보를 만든다.
   기존 배정 생성기를 호출하고 책별로 명시된 활동 예외만 적용한다. DB 쓰기는 없다.
3. 날짜별 제목·활동·횟수·퀴즈와 이미지 해상도·바이트를 검토한다.
4. 실제 등록 요청에서는 기존 도구로 대상 프로젝트·소유·활성 상태·중복·기간 겹침을
   확인한 뒤 허용된 신규 행만 저장한다. 앱의 upsert를 그대로 호출하지 않는다.
5. 저장 후 독립 재조회로 필드와 표지 해시를 비교한다. 응답이 불명확하면 재조회하고
   확인된 누락만 처리한다. 여전히 불명확하면 멈추고 보고한다.
6. 결과 기록의 `prepared`, `applied`, `db_verified`, `app_verified`를 구분한다.
   로그인 앱 확인이 불가능하면 부모 확인 대기로 남긴다.

동시 저장 충돌과 재시도는 별도 시스템으로 개발하지 않는다. 기존 등록 절차의
조회·대조·불명확 시 중단 지침으로 다룬다. 기본 루틴·책별 예외·책 순서는 Prepare
결과에 고정하고 저장 단계에서 재추론하지 않는다.

## Verification

- 스킬 내부 Node 테스트로 정상·경계·잘못된 입력을 확인한다.
- 이미지: 방향·축소·확대 방지·투명 배경·잘못된 파일·파일/픽셀 상한·원본 보존.
- 배치: 등록만, 1/2주, 두 아동, 순서 변경, 책별 예외, URL 필드, 중복 ID,
  잘린 JSON, 누락 파일, 큰 base64를 stdout에 출력하지 않음, 산출물 무결성.
- 테스트는 Given–When–Then을 따른다. 스킬 형식 검사와 계약 검사를 실행한다.
- 변경 전후 범위 밖 파일 해시를 비교한다. 앱 빌드·브라우저 검증·운영 등록은
  스킬 기능 검증을 대신하지 않으며 이번 완료 조건에 포함하지 않는다.

## Out of Scope

앱 공용 모듈, 앱 업로드 경로, 서버 API/Action, DB 스키마/RLS/Storage 변경,
운영 데이터 쓰기, 자동 Apply/재시도/동시성 제어 시스템, QR 알고리즘 변경,
표지 외곽 맞춤·배경 자르기·원근 보정, 기존 표지 일괄 재압축, Git commit/push.

## ADR Decision

앱 아키텍처와 저장 방식을 변경하지 않으므로 ADR과 전역 도메인 모델 변경은 없다.
