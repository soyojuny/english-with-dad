# Step 04 — 기존 도구를 이용한 등록·결과 보고 지침

## What to Build

기존 Supabase 도구로 준비된 후보를 등록·대조하는 운영 지침을 스킬과 참조 문서에
반영한다. 자동 Apply, 트랜잭션/잠금, 재시도 시스템은 구현하지 않는다.

## Acceptance Criteria

- [x] 저장 전 산출물 무결성과 대상 프로젝트·소유·활성·중복·기간 겹침 확인 안내.
- [x] 신규/재사용 구분, 기존 진행 기록 보존, 앱 upsert 무조건 재사용 금지 유지.
- [x] 응답 불명확 시 재조회 → 확인된 누락만 처리 → 여전히 불명확하면 중단 안내.
- [x] 저장 후 전체 요청 필드와 표지 길이·SHA-256 비교 안내.
- [x] 결과 파일에 생성/재사용 ID와 네 상태를 구분. 로그인 앱 미확인은 대기로 기록.
- [x] 스킬과 운영 문서의 브라우저 압축·새 동시성 시스템 요구 제거.
- [x] 이번 개발 과정의 운영 DB 쓰기 없음.

## Required Verification

스킬 형식 검사, 참조 링크·실행 예시 확인, 스킬 테스트와 계약 검사 실행.
범위 밖 기존 파일 해시 일치 확인. 실제 운영 DB·로그인 앱 검증을 완료했다고 쓰지 않는다.
