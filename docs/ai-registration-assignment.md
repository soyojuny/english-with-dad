# AI 자료 등록·할일 배정

## 합의한 작업 방식

2026-10-04 요구사항 인터뷰에서 정한 목표는 부모의 제목 입력, QR 링크 복사,
날짜별 배정 작업을 줄이는 것이다. 우선 앱에 새 기능을 개발하지 않고,
Codex가 사진을 해석해 연결된 Supabase의 기존 자료·배정 테이블에 저장한다.
이 문서는 세션 초기화 후에도 유지할 작업 기준이다.

- 부모가 아동·용도(읽기, 정따, 그림책)별 책과 순서를 정한다.
- 표지·QR 사진을 책 순서대로 제공한다. 제목이나 일별 횟수를 다시 적게 하지 않는다.
- 부모가 시작 일요일과 1주 또는 2주를 지정한다. 일~금에 배정하고 토요일은 쉰다.
- 전체 묶음을 함께 처리하거나 특정 아동·용도 묶음만 처리할 수 있다.
- 사진 인식, 자료 등록, 루틴에 따른 배정을 이어서 처리한다.
- 확실한 정보는 요청 범위 안에서 처리하고, 불확실한 정보만 질문한다.
- 먼저 분석·검토를 요청하면 사진과 기존 데이터 조회로 등록안을 제시하고 DB에 저장하지 않는다.
  후속 실행 요청에서는 검토한 구성에 새로 지정한 날짜·링크·순서를 반영한다.
- 기존 배정과 겹치면 부모가 유지·교체를 선택한다. 완료 기록은 임의로 지우지 않는다.
- 루틴 변경은 새 배정부터 적용한다. 과거·기존 배정은 자동 변경하지 않는다.
- 현재 두 아동은 다른 책을 쓰지만 같은 책을 공유할 수 있다. 책은 부모 계정에 한 번
  등록하고 아동별 배정에서 참조한다. 기존 책 검색을 부모의 추가 작업으로 만들지 않는다.

폴더를 입력 수단으로 사용하는 방안은 가능하지만 구체적인 폴더 형식은 아직 확정하지
않았다. 폴더를 사용해도 사진과 아동·용도·책 순서를 전달하는 데 활용하고,
부모에게 책 제목·날짜·횟수를 매번 수동으로 작성하도록 요구하지 않는다.
폴더 감시, 상시 자동 실행, 앱 UI 개발은 현재 범위에 포함하지 않는다.

## 현재 루틴

실행에 사용하는 규칙은
[routines.json](../.agents/skills/ewd-register-assign/references/routines.json)에 보관한다.
루틴을 변경할 때 이 설명과 규칙을 함께 수정한다. 아동 이름·ID는 첫 실제 배정에서
부모의 지정과 Supabase 조회를 통해 확인한다. 생성 순서만으로 첫째·둘째를 추정하지 않는다.

2026-10-04 책 검토에서 부모가 지정한 김지율은 앱 이름 `골든스피노`,
아동 ID `111e5fcd-be35-480f-8192-8eee41f03ef0`로 확인했다.
첫째·둘째 역할은 이 이름 연결만으로 확정하지 않는다.
이후 부모가 검토안에 이어 10월 11일 신규 배정을 요청하고 그림책 링크와 읽기 순서를
지정했다. 해당 배정에는 검토안의 둘째 1주 루틴을 적용했다.
다음 요청에서는 이 이름 연결과 합의했던 루틴을 복원하고 현재 부모 소유를 재확인한다.
이미 합의한 요청 범위는 반복해서 묻지 않는다. 적용했던 루틴과 가족 내 출생 순서는
구분하며, 책 수만으로 용도·역할·기간을 확정하지 않는다.

2026-10-04 김지온 후속 배정에서 앱 이름 `김지온 킹`, 아동 ID
`919b1219-6b55-479a-96cd-d00f362df9cb`의 부모 소유를 재확인하고 첫째 루틴을 적용했다.
부모가 읽기는 `The Minotaur` → `The Monster Gang` → `The Sorcerer's Apprentice`,
정따는 `The Maple Harvest` → `Henry and Mudge and Annie's Good Move` 순서로 지정했다.
부모의 최종 정정: 이번 두 정따 책에는 읽기 오디오가 없으므로 읽기를 제외한다.
정따 링크는 정따 필드에만 저장하며 정따·스스로 읽기 각 1회와 문제풀이를 유지한다.
이 규칙을 첫째 정따 루틴에 반영하고, 명시적으로 요청한 10월 11~16일의 정따 배정
6행에서 읽기를 제거했다. 두 책에 중복 저장했던 읽기 링크도 비웠다.

| 용도 | 첫째 | 둘째 |
|---|---|---|
| 읽기 | 1권씩 2일. 1주 3권·2주 6권. 매일 읽기 1회 + 문제풀이 | 2권씩 3일. 1주 4권·2주 8권. 매일 각 책 읽기 1회 |
| 정따 | 1권씩 3일. 1주 2권·2주 4권. 기본: 매일 정따·스스로 읽기 각 1회 + 문제풀이 | 1권씩 6일. 1주 1권·2주 2권. 매일 읽기·정따·스스로 읽기 각 1회 |
| 그림책 | 2권씩 6일. 1주 2권·2주 4권. 매일 각 책 오디오 읽기 1회 | 첫째와 동일 |

2026-10-05 확인한 첫째 정따의 기본은 정따 링크 하나이며, 별도 읽기는 배정하지 않는다.
현재 ORT에만 별도 읽기 링크가 있는 예외가 있다. 이 조건은 나중에 바뀔 수 있으므로
시리즈명만으로 읽기를 자동 추가하지 않고, 해당 책의 링크와 합의된 배정 활동을 확인한다.
`routines.json`은 기본 루틴이며 책별 예외는 이 운영 문서와 부모의 최신 지정에 따라 적용한다.
링크 개수나 오디오 내용만으로 배정 활동을 늘리지 않는다.

둘째 정따는 2026-10-04 후속 대화에서 수정한 규칙이다. 이전의 2일 단위 단계별
횟수 규칙은 사용하지 않는다. 문제풀이는 첫째 읽기·정따를 배정하는 매일 포함한다.

용도와 앱의 활동 구분은 다음처럼 연결한다. `listen`의 화면 이름은 ‘읽기’이며
인터뷰에서 말한 오디오 듣기에 해당한다.

| 용도 | 활동 구분 | 과제 |
|---|---|---|
| 읽기 | `focusListen` (집중듣기) | `listen` |
| 정따 | `readAloud` (소리내어 읽기) | 첫째 기본: `shadow`, `self`; 둘째: `listen`, `shadow`, `self` |
| 그림책 | `englishPicture` (영어 그림책) | `listen` |

## 사진과 링크

- 대부분의 책에 있는 표지·QR 번호로 사진을 연결한다. 앞자리 0을 제외한
  `06873`과 `6873`은 같은 번호로 볼 수 있다. 번호는 배정 순서를 결정하지 않는다.
- `English w. M 29`는 모든 책에 붙은 공통 스티커라 책별 시리즈 판단에 쓰지 않는다.
- 시리즈 입력값과 배정 용도는 별개다. 사진에서 시리즈를 확인하지 못하면 부모가
  지정한 묶음 이름을 사용한다. 이번 Leo의 시리즈 입력값은 ‘그림책’이다.
- 일부 책만 QR이 두 개 있다. QR 옆 문구와 부모의 용도 지정으로 읽기·정따를 구분한다.
- QR은 우선 무료 디코더로 처리한다. 실제 Leo 사진은 원본에서 jsQR·ZXing 모두
  실패했지만 전체 사진을 가로·세로 각각 1/4로 줄이면 두 디코더 모두 성공했다.
- QR 원문에 `URL:`이 있으면 실제 HTTP(S) 주소를 추출한다. 디코더 간 결과가 다르면
  확정하지 않는다. 실패하면 인식한 정보는 유지하고 실패한 링크만 부모에게 받는다.
- 부모가 직접 준 HTTP(S) 읽기·정따 링크도 사용한다. YouTube 링크와 쿼리 매개변수를
  그대로 보존하며 QR 사진을 추가 요구하지 않는다. 주소 인식과 실제 재생 확인은 구분한다.
- 김지율 사진에서는 전체 사진 처리로 QR 3개, 영역 자르기·축소·이진화로 나머지
  3개를 추출했다. 재사용 도구와 입력·재시도 방법은
  [사진 처리 참조](../.agents/skills/ewd-register-assign/references/photo-processing.md)에 보관한다.
- 표지는 앱의 `lib/cover-image.ts`를 사용해 최대 변 960px, JPEG 품질 0.72로 압축하고
  기존 방식대로 `books.cover`에 data URL을 저장한다.
- 정따용 QR에 읽기와 정따 오디오가 모두 포함되는 사례를 확인했다. 같은 URL을 두
  필드에 넣는 것은 읽기·정따가 모두 합의된 배정 활동이고 해당 책의 공용 링크임이
  확인된 경우에만 한다. 현재 앱은 읽기·정따
  링크를 각 필드에서 가져오며 빈 읽기 링크를 정따 링크로 자동 대체하지 않는다.

## 처리·검증 기준

한 번에 약 20권, 월 약 40권을 기준으로 한다. QR 20개 중 15~17개 이상 자동 처리하고,
실패한 3~5개 링크는 수동 보완하는 수준을 목표로 한다. 사진 제공 후 인식·배정에
2~5분 정도 기다릴 수 있다. 한 장의 성공으로 전체 인식률을 검증했다고 보고하지 않는다.

앱 구현을 다시 검토할 때는 Google 무료 티어를 우선 비교하되 개발·유지 부담이 커지면
소액 GPT API 비용을 허용한다. 현재 직접 처리 방식에서는 별도 API 선택·구매를 진행하지 않는다.

저장 전에 대상 프로젝트·부모 계정·아동 소유·자료 소유와 활성 상태·필요한 오디오를
확인한다. 자료 중복 및 아동·활동 구분·기간의 기존 배정을 다시 조회한다.
배정 스크립트는 날짜별 행만 생성하며 DB에 접속하거나 저장하지 않는다.

저장 후에는 행을 재조회해 소유·날짜·자료·활동·횟수·퀴즈와 행 수를 비교한다.
앱에서 아동 할일 표시와 오디오 실행도 확인한다. 로그인 세션이 없으면 저장 데이터
검증과 로컬 화면 확인을 실제 로그인 검증과 구분해 보고하고 부모의 화면 확인을 받는다.
부분 실패나 저장 응답 불명확 시 먼저 재조회하고 확인된 누락만 재시도한다.
표지 포함 데이터가 도구 출력 한도를 넘으면 분할 전달 후 길이·해시와 JSON 완전성을
확인한다. 상세 절차는 위 사진 처리 참조를 따른다.
